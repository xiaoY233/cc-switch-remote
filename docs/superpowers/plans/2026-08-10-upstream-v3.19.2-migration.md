# Upstream v3.19.2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge the exact upstream v3.19.2 release into CC Switch Remote while preserving fork identity, README content, release configuration, data isolation, and remote-management parity.

**Architecture:** Keep upstream ancestry with a stable-tag merge, then resolve fork overlap by retaining target-aware frontend adapters and shared Rust service logic. Remote operations continue through thin helper JSON commands keyed by the selected remote profile; local operations keep upstream-compatible paths. Fork identity and release-chain files are treated as controlled state and mechanically compared with the v3.19.1 fork parent.

**Tech Stack:** Git, React 18, TypeScript, TanStack Query, Vitest, Tauri 2, Rust, rusqlite, SSH JSON helper protocol, GitHub Actions.

## Global Constraints

- Upstream baseline is exactly annotated tag `v3.19.2`, peeled commit `43eaf07355af145aebfee301801779e824d4c221`.
- Do not include any upstream `main` commit after `43eaf07355af145aebfee301801779e824d4c221`.
- Keep `README.md`, `README_ZH.md`, `README_JA.md`, and `README_DE.md` byte-for-byte identical to fork commit `4b0f8af8`.
- Preserve product name `CC Switch Remote`, Cargo package `cc-switch-remote`, binaries `cc-switch-remote` and `cc-switch-remote-helper`, repository `https://github.com/xiaoY233/cc-switch-remote`, Tauri identifier `com.ccswitch.remote`, and deep-link schemes `ccswitch` plus `ccswitch-remote`.
- Preserve the fork updater endpoint, updater public key, helper artifacts, signing validation, release asset naming, release-maintenance workflow, and application data directory `.cc-switch-remote`.
- Development/debug builds must not use installed-release data unless the user explicitly opts in after a backup.
- Remote mutations must use the selected remote profile, preserve prior state on command failure, keep a usable long-lived helper session alive, refresh target-qualified state, and show localized feedback.
- Remote helper commands must be thin adapters over shared Rust core/service logic.
- Do not push branches, create tags, publish artifacts, or create a GitHub release as part of this plan.

# CC Switch Remote v3.16.13

> **上游基线**：CC Switch `v3.16.5`
>
> **远程版构建**：`cc-switch-remote v3.16.13`
>
> 本版本聚焦远程管理稳定性：新增远程路由 daemon/systemd 管理模式，修复远程路由状态显示漂移，并改善远程 SSH、helper 和应用更新失败时的错误提示。

---

## 重要更新

### 远程路由支持 daemon/systemd 管理模式

远程路由运行时不再只能依附于桌面客户端维持的 SSH helper session。

新版 helper 新增：

- `routing-runtime daemon-start`
- `routing-runtime daemon-stop`
- `routing-runtime daemon-status`
- `routing-runtime daemon-run`

启动远程路由时会优先创建并启动 `systemd --user` service；如果远程环境没有可用的 user systemd，会自动回退为 detached helper 后台进程。

这意味着客户端关闭、重启或 SSH session 重建后，远程路由和 helper 运行时仍可继续在远程服务器上保持服务。

### 远程路由状态以真实运行态为准

远程路由状态读取现在会探测远程 proxy 的 `/status`，而不是只看远程配置中的 enabled 标记。

这修复了以下体验问题：

1. 远程路由实际已经停止，但重新打开客户端后首页开关仍显示开启。
2. 首页远程路由开关和设置页路由运行状态偶尔不一致。
3. app routing 子开关显示配置为启用，但运行时已经不存在。

现在 UI 会以真实运行中的远程路由为准显示状态。

### 远程 SSH / helper 错误提示更直观

远程连接失败时会对常见 SSH 错误进行归一化提示，包括：

- 远程主机密钥变更。
- SSH 认证失败。
- 连接被拒绝或超时。
- DNS / 主机名解析失败。
- helper 文件不存在或路径错误。

例如 `no such file or directory: /root/.local/bin/cc-switch-remote-helper` 会提示为 helper 路径不可用，而不是直接展示低层 shell 报错。

### 应用内更新失败提示和下载代理优化

应用内检查更新失败时会展示具体错误，并提供打开 GitHub Release 页的兜底入口。

Tauri updater 现在会读取全局代理配置并传给更新器，改善“浏览器能下载安装包，但应用内检查/下载更新失败”的情况。

---

## 远程 Helper

请在升级桌面应用后，到远程服务器管理页面更新 helper，才能使用 daemon/systemd 远程路由模式。

- Helper release tag: `remote-helper-latest`
- 支持目标：Linux x86_64、Linux arm64、macOS universal
- Helper 仍然是无 Tauri 桌面依赖的纯 Rust CLI 构建

# CC Switch Remote v3.16.9

> **上游基线**：CC Switch `v3.16.3`
>
> **远程版构建**：`cc-switch-remote v3.16.9`
>
> 本版本聚焦远程服务器管理热修：修复远程 Codex OAuth 路由认证、Claude Code Linux 安装后的 PATH 可执行性，以及远程统一供应商编辑时 API Key 留空无法保存的问题。

---

## 重要修复

### 远程 Codex OAuth 路由可正确使用远程 Token

远程 helper 的路由运行时现在会注入 helper 自己持有的 Codex OAuth / Copilot 托管认证管理器。

这修复了以下场景：

1. 在远程服务器上完成 Codex OAuth 登录。
2. 添加 Claude Code 的 Codex OAuth 反代供应商。
3. 开启 Claude Code 远程路由。
4. Claude Code 请求只显示 `API error · Retrying`，但远程路由实际没有拿到远程 OAuth token。

本版本后，远程路由会优先从远程 helper 的认证运行时解析 ChatGPT access token；桌面本地路径仍沿用原来的 Tauri 状态，不改变上游本地行为。

### Claude Code 远程安装后自动修复 PATH

Claude Code 官方 Linux 安装脚本可能把二进制放到：

```text
~/.local/bin/claude
```

但某些 SSH / WindTerm 会话不会自动加载该目录，导致只能手动运行：

```bash
/root/.local/bin/claude
```

本版本在远程 helper 执行工具安装后，会检测已安装的可执行文件路径，并在需要时把对应目录追加到常见 shell 启动文件，避免后续 SSH 会话找不到 `claude`。

### 远程统一供应商编辑可留空 API Key

远程编辑已有统一供应商时，API Key 留空现在表示“保留远程已有密钥”。

之前即使供应商已经添加过，编辑保存时仍会提示：

```text
请先填写 API Key
```

本版本修复了该校验逻辑，并确保不会提交空值覆盖远程已有密钥。

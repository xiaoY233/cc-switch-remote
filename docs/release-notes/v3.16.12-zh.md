# CC Switch Remote v3.16.12

> **上游基线**：CC Switch `v3.16.5`
>
> **远程版构建**：`cc-switch-remote v3.16.12`
>
> 本版本合并上游 v3.16.5 发布线，并继续保留远程管理 target 隔离、远程 helper 共享 Rust 服务逻辑，以及远程 provider / session / auth / model fetch 的适配边界。

---

## 重要更新

### 合并上游 v3.16.5 发布线

本版本吸收上游 v3.16.5 的主要改动，包括 Codex 原生 Responses 模型目录生成、拒收 `web_search` 的原生网关自动禁用、Codex 模型映射与本地路由开关解耦、Claude 通用配置切换前自动同步、Claude Sonnet 5 定价与默认档升级、会话分类视图与分组管理，以及新增 Qiniu、FennoAI、ZetaAPI、TeamoRouter、NekoCode、Code0.ai、Amux 等供应商预设。

本次合并继续以上游已发布 tag 作为稳定基线，没有默认合入上游发布后的 main 追加提交。

### 远程管理适配

本版本确认以下上游新增能力在远程管理路径中继续复用共享逻辑：

- 远程 `providers add/update/switch` 继续通过 helper 调用共享 `ProviderService`，因此 Codex 原生 Responses 模型目录、`web_search` 黑名单、通用配置自动同步、usage script 凭据归一化等逻辑会在远程服务器状态上生效。
- 远程模型列表获取继续使用远端 provider 与远端已保存密钥，编辑供应商时 API Key 留空仍表示保留远端已有密钥。
- 会话分类视图复用同一组件，但 query key 与消息/删除操作继续带 remote target，远程会话不会混入本地会话。
- Claude Desktop 状态、Omo/OpenCode live provider ids 等本地 live 状态读取继续被 local-only guard 保护，不会在远程页面误读本机状态。

### UI 与预设同步

上游的长下拉滚动边界、窄弹层日期选择器、Claude Desktop / OpenClaw / Hermes API Key 链接、供应商图标体积优化和新增预设已合并到远程版共享前端。

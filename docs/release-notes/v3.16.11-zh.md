# CC Switch Remote v3.16.11

> **上游基线**：CC Switch `v3.16.4`
>
> **远程版构建**：`cc-switch-remote v3.16.11`
>
> 本版本合并上游 v3.16.4 发布线，并保留本项目远程管理边界与近期远程路由、供应商、工具调用转换相关修复。

---

## 重要更新

### 合并上游 v3.16.4 发布线

本版本吸收上游 v3.16.4 的主要改动，包括 Codex 原生 Responses 支持、代理请求覆盖、请求体解压与 zstd 支持、SubRouter 预设、Doubao Seed 2.1 Pro/Turbo 定价、Volcengine 用量查询增强、数据库升级恢复界面、Windows ARM64 发布支持，以及 Hermes/usage script 等后续修复。

后续合并上游时将以已发布版本 tag 为稳定基线。上游发布后的 main 追加提交会单独列出和评估，不再默认作为稳定发布内容全部合入。

### 保留远程管理 target 隔离

远程管理相关的 provider、usage、skills、模型列表、路由状态和 helper runtime 继续保持 target-aware 路径：

- 远程目标不会把本地账号、API Key、用量缓存或代理接管状态作为远程状态来源。
- 远程模型列表和定价导入继续携带当前远程 target。
- provider 更新后的缓存刷新继续按 local/remote target 分桶。
- 远程路由关闭后会刷新应用级路由配置缓存，避免首页和设置页状态不一致。

### Codex/Claude 工具调用转换防护

本版本保留并验证了 Codex Chat/Responses 工具调用转换中的防护逻辑：

- 空 `call_id` 会被合成有效 ID。
- 缺失函数名的工具调用会被跳过，避免生成无效 Responses payload。
- streaming 与非 streaming 工具调用路径均有回归测试覆盖。

### DeepSeek 官方 Anthropic 端点兼容

当 DeepSeek 官方 Anthropic 兼容端点收到 `thinking: { type: "disabled" }` 与 effort 参数同时存在的请求时，本版本会移除冲突的 effort 字段，避免上游 400 错误，同时保留 `thinking: disabled` 的语义。

# CC Switch Remote v3.20.0

本版以 CC Switch 上游 `v3.20.0` 正式标签为稳定基线，同步 Pi 原生管理、Codex 多账号 ChatGPT 管理、Claude Code 托管 WebSearch 与 Codex Alpha Search、Windows WSL 路径与 CLI 检测、备份/同步加固等更新，并完成 CC Switch Remote 的本地/远程目标适配、共享实现合并与 schema v17 发布边界审计。

## 主要更新

- 上游新增 Pi 作为第九个托管应用（`~/.pi/agent/models.json` 供应商管理、Prompt 库、Skills、会话浏览器），以及 schema v16 → v17 迁移（新增设备本地的 `session_usage_dedup` 表）。
- Codex 多账号 ChatGPT 管理：Auth Center 支持多个 Codex OAuth 登录，供应商卡片可按账号绑定或跟随 CLI 登录；账号切换写入 `~/.codex/auth.json` 并支持自刷新。
- Claude Code 内置 WebSearch 在路由到 Responses/Codex OAuth 后端时可用；本地代理新增对 Codex 独立 Alpha Search 端点的支持。
- Windows WSL 路径写入、CLI 检测（注册表 PATH 与独立安装目录）、启动白/黑闪屏、MSI 垃圾注册表键等修复同步到稳定基线。
- 备份 SQL 往返、恢复投影、单实例串行、DeepSeek V4 重新定价、macOS IME 修复同步到稳定基线。

## 远程管理与共享实现合并

- Codex OAuth 凭证所有权收敛为单一 `Arc<CodexOAuthManager>`：桌面 `AppState` 持有并在整个代理链路（ProxyServer → RequestForwarder、非桌面 failover、恢复命令）共享同一个 manager，作为 `auth.json` 写入的唯一仲裁者。Fork 的 `ManagedAuthRuntime` 收窄为仅 `copilot` 与 `xai_oauth`，不再持有 Codex。
- 远程 Helper 进程级 `CODEX_OAUTH_MANAGER` 注入到每个 `AppState`；所有 Helper 的 `AppState::new` 统一经共享工厂 `build_remote_app_state`，本地与远程共用同一 Rust 实现，无复制/分叉逻辑。
- Codex 账号选择（按卡片绑定、跟随 CLI）与账号切换在远程目标上经 Helper 命令执行，不触碰本地 `~/.codex/auth.json` 或本地 OAuth 状态；远程目标不暴露本地浏览器/OAuth 副作用。
- Pi 与共享 `tool_environment::run_tool_lifecycle_action`（4 参）保持本地/远程共用实现，远程 Helper 同步 Pi 工具生命周期检查。

## 升级说明

- 应用版本、Cargo 版本与 Tauri 版本统一为 `3.20.0`；数据库 schema 升级到 v17。
- v16 → v17 迁移需在开发/发布数据隔离下验证：开发构建不得对已安装应用的数据目录执行迁移（会令已安装应用拒绝启动）。升级前请先确认数据库路径、`user_version` 与本次发布支持的 schema 版本。
- 正常启动时可通过“设置 → 关于 → 检查更新”升级；数据库恢复界面的更新命令不依赖已初始化的 `AppState`。
- Remote Helper 由远程服务器管理页安装或更新，最新资产发布到 `remote-helper-latest`。
- 更新器元数据、下载地址和签名公钥均指向 `xiaoY233/cc-switch-remote`；`latest.json` 会在全部平台资产上传后生成并校验签名 key id。
- 本次发布不会合入上游 `v3.20.0` 标签之后的提交。

# CC Switch Remote v3.16.7

> **上游基线**：CC Switch `v3.16.3`
>
> **远程版构建**：`cc-switch-remote v3.16.7`
>
> **变更范围**：`v3.16.6...v3.16.7`，包含 9 个提交、95 个文件变更。
>
> `v3.16.6` 已经发布过，因此本轮推进到 `v3.16.7`，保证 Tauri updater 可以从旧版本正常升级。

---

## 概览

本版是远程管理能力的完整补齐版本，不只是文档更新。它在 `v3.16.6` 基础上继续推进远程设置、远程高级、远程认证、远程使用统计、远程路由、Helper 安装/更新和发布文档，目标是让远程目标尽量复用本地页面与业务逻辑，同时保持本地和远程状态独立。

---

## 远程设置与页面对齐

- 远程设置页面继续向本地设置页面结构对齐，保留本地设置模块的菜单顺序、标题和组件边界。
- 远程设置默认入口和本地/远程切换后的页面状态做了修正，减少切换目标后落到不存在页面或跳回错误菜单的问题。
- 新增远程功能对齐表，明确每个模块是 `parity`、`remote-adapted`、`local-only` 还是后续计划。
- 修正本地 App 更新入口在远程目标下的行为：更新的是桌面应用时，入口仍指向本地关于页，不误进入远程设置。

---

## 远程路由与运行态

- 远程首页路由入口与本地首页逻辑对齐：不再额外展示一个远程运行态主开关，而是按本地语义显示应用路由和故障转移入口。
- 开启远程应用路由时，会先确保远程路由运行态可用，再启用对应应用路由，减少“配置已开但远程路由没启动”的不一致状态。
- 远程路由设置页继续复用本地路由的分组结构，覆盖远程路由、远程自动故障转移、远程整流器/优化器、远程全局出站代理。
- 增加远程路由相关回归测试，覆盖首页开关、整流器、全局出站代理和失败保护场景。
- 远程路由失败时遵守 failure-preserving 语义：命令级失败不应关闭已有远程运行态，除非 SSH transport 或 Helper session 本身不可用。

---

## 远程高级设置

- 远程高级设置补齐“配置目录覆盖”，支持远程工具配置目录和远程 CC Switch 配置目录读取。
- 远程备份与恢复接入远程主机数据库，不再只操作本地备份。
- 远程云同步设置迁移完成，WebDAV / S3 相关设置和操作以当前远程主机为目标。
- 远程日志配置通过 Helper 读写，保持与本地高级设置的交互结构一致。
- 高级设置相关 UI 支持、路径处理、能力判断和测试均改为 target-aware。

---

## 远程认证

- 远程认证中心接入 managed auth 设置，支持在远程目标下管理 Codex OAuth、Copilot 等认证相关状态。
- Helper 新增认证相关命令和 capability，桌面端通过远程 API 调用，不把本地认证状态当作远程状态。
- 供应商表单中的 OAuth / Copilot 授权交互改为可感知当前管理目标。
- 增加远程认证 API 测试，覆盖本地/远程行为拆分。

---

## 远程使用统计

- 使用统计页面接入远程目标，支持远程数据源、趋势图、请求日志、模型统计、供应商统计和 Hero 汇总。
- 远程用量统计复用 shared usage service，并通过 Helper 读取远程主机数据。
- 远程 pricing 配置、模型测试配置和 request log 查询改为 target-aware，避免读取本地统计数据。
- 使用统计事件刷新按目标隔离，避免本地和远程缓存互相污染。
- 增加远程 usage API、target query、pricing/proxy 相关测试。

---

## Helper 安装、更新与健康检查

- 改进远程 Helper 安装/更新体验，Helper 安装完成后会重启远程 session，避免旧 session 继续暴露旧 capability。
- 远程健康检查展示 Helper 版本和构建信息时，使用更清晰的版本 + 构建标识，内部仍使用 commit/build 做兼容性比较。
- 改进 Helper 下载、上传 fallback 和 SSH 临时路径处理，减少因远程主机无法直接访问 GitHub 或 Unix socket 路径过长导致的失败。
- 未安装、能力不足、下载到桌面二进制、缺少运行依赖等情况会给出更明确的错误提示。
- Helper 本版已通过 `remote-helper-latest` 发布，包含 Linux x86_64、Linux arm64、macOS universal 构建。

## 升级提醒

- 更新桌面应用后，建议进入“远程服务器”页面检查每台远程主机的 Helper 是否为最新构建。
- 如果使用远程路由、远程供应商、远程工具环境、远程认证、远程高级设置或远程使用统计，请升级后先执行一次健康检查。
- macOS 构建当前未进行 Apple Developer ID 签名和公证，首次打开可能需要在系统设置中手动允许。

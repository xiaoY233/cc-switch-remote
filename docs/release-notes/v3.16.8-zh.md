# CC Switch Remote v3.16.8

> **上游基线**：CC Switch `v3.16.3`
>
> **远程版构建**：`cc-switch-remote v3.16.8`
>
> 本版本是数据目录隔离热修版本，用于修复 CC Switch Remote 复用上游 `~/.cc-switch` 目录后，导致原版 CC Switch 因数据库 schema 过新而无法启动的问题。

---

## 重要修复

### 远程版默认使用独立数据目录

CC Switch Remote 现在默认使用：

```text
~/.cc-switch-remote
```

不再默认使用原版 CC Switch 的：

```text
~/.cc-switch
```

这可以避免远程版把原版数据库升级到更高 schema 后，原版应用因为“数据库版本过新”而拒绝启动。

### 首次启动复制旧目录，不原地升级

如果用户之前已经使用过远程版，并且本机存在 `~/.cc-switch`，但还没有 `~/.cc-switch-remote`，新版本首次启动会复制一份旧目录到 `~/.cc-switch-remote`。

之后远程版只迁移和写入复制后的目录，原版 `~/.cc-switch` 不再被远程版继续升级。

### Helper 同步隔离

远程 Helper 也改为默认使用 `~/.cc-switch-remote`，并在处理 JSON 命令或长连接 `serve` 前初始化隔离目录。这样远程主机上如果同时安装原版 CC Switch，也不会被远程 Helper 升级原版数据库。

---

## 已知恢复方式

如果已经遇到原版 CC Switch 启动时报错：

```text
数据库版本过新（11），当前应用仅支持 10
```

处理方式：

1. 先备份整个 `~/.cc-switch` 目录。
2. 把当前 schema 11 数据库复制到 `~/.cc-switch-remote/cc-switch.db`，供 CC Switch Remote 继续使用。
3. 从 `~/.cc-switch/backups/` 中选择 schema 10 的备份恢复到 `~/.cc-switch/cc-switch.db`。
4. 原版 CC Switch 继续使用 `~/.cc-switch`，CC Switch Remote 使用 `~/.cc-switch-remote`。

本次本机已执行过等价恢复：原版目录恢复为 schema 10，远程版目录保留 schema 11。

# CC Switch Remote v3.16.10

> **上游基线**：CC Switch `v3.16.3`
>
> **远程版构建**：`cc-switch-remote v3.16.10`
>
> 本版本继续收敛远程管理与本地工作流的功能漂移，重点修复远程托管认证、用量与模型查询、路由状态、会话管理以及远程设置页中误触本地状态的问题。

---

## 重要修复

### 远程托管认证与模型/额度查询使用远程账号

Codex OAuth、GitHub Copilot OAuth、订阅额度、余额、Coding Plan、Copilot 用量和模型列表查询现在都会携带当前管理目标。

这修复了远程管理中可能出现的本地账号串入远程视图、远程 Claude/Codex 供应商无法正确取模型或额度的问题。

### 远程设置不再触碰本机 Codex 历史备份

远程 General 设置页复用本地 Codex Auth 设置时，现在会按 target 隔离：

- 本地目标仍保留原有 Codex 统一历史备份探测和恢复逻辑。
- 远程目标只保存远程设置，不再调用本机 `has_codex_unify_history_backup` 或 `restore_codex_unified_history`。

### 远程会话页不再启动本机终端

远程 Sessions 视图不会暴露本地终端恢复入口，内部恢复 handler 也会在远程目标下避免调用本机 `launch_session_terminal`。

远程会话属于远程主机，桌面端不应把远程 resume 命令拿到本机终端执行。

### 远程路由与故障转移状态继续隔离

远程代理状态、应用路由、故障转移队列、熔断器健康状态和相关缓存 key 继续按目标隔离，避免本地代理接管状态影响远程供应商切换判断。

本版本也补强了远程 helper 对无 payload 成功响应的处理，命令级失败不会错误关闭长生命周期 helper 会话。

### 远程功能漂移审计规则落地

项目规则新增远程漂移审计方法，要求后续所有远程管理改动必须从本地完整调用链开始对齐，而不是只以页面是否渲染、是否有 helper command 作为完成标准。

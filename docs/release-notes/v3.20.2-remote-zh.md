# CC Switch Remote v3.20.2

本版以 CC Switch 上游 `v3.20.1` 正式标签为稳定基线，完整迁移其 Codex 认证、供应商切换、配置写入、会话用量和恢复修复，并保留 CC Switch Remote 的产品身份、独立数据目录、更新器、签名与 Remote Helper 架构。

## 主要更新

- Codex 托管认证支持 workspace 成员身份隔离、定向重新登录与取消登录；本地账号 ID、OIDC subject 和 workspace ID 不再混用。
- 第三方 Codex 密钥采用 config-only 模式，只写入自定义 provider 的 `experimental_bearer_token`，不会创建或覆盖官方 OAuth `auth.json`。
- Codex 切换增加预检查、切换锁和事务回滚；失败时精确恢复当前供应商、Live 配置、认证文件、备份和运行中路由。
- 数据库 schema 从 v17 升级到 v18，会话扫描增加字节游标、尾部指纹、延迟尾部重试及同尺寸改写检测。
- SQL、WebDAV、S3 与备份恢复统一复用共享 Rust restore service；迁移前备份必须完成关闭、fsync、只读重开和 `quick_check` 验证，否则停止迁移。
- Codex 目录推理级别、托管账号卡片身份/额度、Pi 模型获取、OpenCode Go/Token Plan、Prompt 恢复和 TeamoRouter 预设同步到稳定行为。

## 远程管理与 Helper 兼容

- Remote Helper 继续复用桌面端的共享 Rust OAuth、Provider、Restore、Usage 与切换服务，不复制业务逻辑，也不成为本地密钥真源。
- 新增 `auth-targeted-relogin`、`auth-cancel-login`、`codex-config-only` 和 `usage-manual-session-sync` capability。
- 旧 Helper 仍可执行已支持的 provider、账号列表和基础认证操作；缺少 capability 的新操作会在发送 mutation 前返回升级提示，不回退到本地 Tauri 命令，也不会关闭长寿命 Helper session。
- 远程 Codex 配置写入必须具备 `codex-config-only`；远程认证入口必须具备 `auth`，并按细分 capability 降级定向重新登录和取消操作。
- 远程会话同步仅提供用户显式触发的手动同步；桌面后台自动扫描保持 local-only。
- 远程模型列表始终经所选 profile 的 Helper 获取，即使编辑表单中存在未保存的 API key，也不会把请求或密钥转到本机执行。

## 升级说明

- 应用、Cargo、Tauri、lockfile 和发布一致性检查版本统一为 `3.20.2`。
- schema v18 会在升级前创建并验证备份。旧版 `v3.20.1` Helper 不支持打开 v18 数据库；升级桌面应用后应同步更新每台远程主机上的 Helper。
- schema 升级不可通过旧 Helper 原地降级。需要回退时，应使用升级前备份恢复对应主机的数据目录。
- 正常启动时可通过“设置 → 关于 → 检查更新”升级；数据库恢复界面的更新命令不依赖已初始化的 `AppState`。
- 更新器 endpoint、公钥、下载地址和 Helper 资产继续指向 `xiaoY233/cc-switch-remote`；本次准备不创建标签、不发布 Release。
- 本次迁移仅包含上游 `v3.20.1` 标签提交 `3217f72596f2d1c0f879f0a05f83803825d9809f`，不包含该标签之后的上游提交。

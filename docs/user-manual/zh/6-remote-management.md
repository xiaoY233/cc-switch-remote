# 6.1 远程服务器管理

远程服务器管理把桌面端作为控制台，把远程主机作为实际执行目标。桌面端通过 SSH 连接远程主机，并调用远程主机上的 `cc-switch-remote-helper`。供应商配置、API Key、MCP、Prompts、Skills、工具配置、数据库、备份和用量数据都属于远程主机自己，不会自动从本机复制过去。

## 基本流程

1. 打开左侧“远程服务器”。
2. 添加远程主机，填写主机地址、端口、用户名和认证方式。
3. 执行健康检查。
4. 安装或更新远程 Helper。
5. 在顶部目标切换器中选择该远程主机。
6. 在供应商、设置、MCP、Prompts、Skills、会话、工具环境等页面进行管理。

如果远程主机使用密码登录，密码用于 SSH 连接配置，不等同于供应商 API Key。供应商 API Key 应留在远程主机自己的配置中。

## Helper 生命周期

远程 Helper 是远程管理的执行层。应用页面上的“安装 Helper / 更新 Helper / 健康检查”会在远程主机上完成以下事情：

- 检查 `~/.local/bin/cc-switch-remote-helper` 是否存在。
- 查询 Helper 版本和构建信息。
- 检查 Helper 是否包含当前应用需要的 capabilities。
- 从 GitHub `remote-helper-latest` release 下载匹配远程系统架构的二进制。
- 更新后重新执行健康检查。

常见状态含义：

| 状态 | 含义 | 建议 |
|------|------|------|
| 未安装 | 远程主机没有 Helper | 点击安装 Helper |
| 已安装 | Helper 可执行且能力满足当前页面 | 可以继续管理 |
| 有新版 | GitHub 上存在更新构建 | 点击更新 Helper |
| 能力不足 | Helper 太旧，缺少当前功能命令 | 更新 Helper 后再操作 |
| 无法运行 | 二进制不兼容或缺依赖 | 重新安装纯 CLI Helper，避免下载桌面应用二进制 |

手动排查命令：

```bash
~/.local/bin/cc-switch-remote-helper --version
~/.local/bin/cc-switch-remote-helper --json status
```

## 远程供应商

远程供应商页面应与本地供应商页面保持一致，但目标是远程主机：

- 添加、编辑、删除和排序供应商作用于远程数据库。
- 统一供应商配置写入远程主机。
- API Key 编辑时如果留空，表示保留远程主机已有密钥。
- 读取配置 JSON 时不能混入本机 JSON。
- 切换供应商会写入远程主机上的对应 CLI 配置文件。

如果编辑页显示 `[redacted]`，代表密钥被脱敏展示。保存时只要不重新填写该字段，就应保留远程原密钥。

## 远程设置

远程设置复用本地设置模块，但保存位置是远程主机：

- 通用：主页面应用显示、Skills 存储位置、Skills 同步方式、Codex 应用增强、Claude Code 插件相关选项。
- 路由：远程路由、远程自动故障转移、远程整流器、远程全局出站代理。
- 认证：远程主机上的账号和授权状态。
- 高级：远程配置目录覆盖、导入导出、备份恢复、云同步、日志配置。
- 使用统计：读取远程主机的使用记录、供应商用量和统计配置。
- 关于：本地 App 更新属于本机；远程工具环境检查和安装冲突诊断属于远程主机。

本地 UI 语言、主题、窗口行为、系统托盘、桌面深链、本机更新等能力不应该作为远程设置保存。

## 远程路由

远程路由运行在远程主机上，不是本机代理：

- 首页远程路由开关应遵守与本地首页相同的依赖逻辑。
- 开启应用路由前，需要确保远程路由运行态可用。
- 自动故障转移队列、熔断器、供应商健康状态必须读取远程状态。
- 整流器和优化器配置必须作用于远程路由。
- 全局出站代理表示远程主机访问上游供应商时使用的代理，不是桌面端网络代理。

远程命令失败时，不应因为一个设置保存失败就停止已经运行的远程路由。只有 SSH 连接或 Helper session 本身不可用时，才需要重连。

## MCP、Prompts、Skills 和会话

这些功能都以当前目标为准：

- 选择本地目标时，读写本机配置。
- 选择远程目标时，读写远程主机配置。
- 远程 Skills 支持存储位置和同步方式设置。
- 远程会话和 Hermes Memory 读取远程主机上的历史数据。
- 暂不支持或不安全的恢复动作应隐藏、禁用或说明原因，不能显示成可点击但无反应。

## 工具环境与更新

远程工具环境检查在远程主机执行，结果反映远程主机是否安装了 Claude Code、Codex、Gemini CLI、OpenCode、OpenClaw、Hermes 等工具。

注意：

- `npm`、`cargo`、`bash`、`curl` 等命令是否可用，以远程 SSH 非交互 shell 的 PATH 为准。
- 如果远程终端手动执行可用，但应用内显示不可用，需要检查非交互 shell 的 PATH 初始化。
- “本地 App 检查更新”只更新桌面应用；远程 Helper 更新在远程服务器页面执行。

## 本地专属能力

以下能力默认属于本机，不应直接迁移为远程设置：

- 桌面应用自动更新。
- 本地系统托盘和托盘快速切换。
- 本地窗口行为、主题、语言。
- 本地终端启动。
- 本地桌面深链回调。
- 依赖本机浏览器回调地址的 OAuth 流程。

设备码授权可以远程管理，因为浏览器只负责确认代码，轮询和 token 存储由远程 Helper 完成。

## 发布前检查

发布完整版本前建议确认：

- 桌面应用 release 已成功生成目标平台资产。
- `remote-helper-latest` 已包含最终 commit 构建的 Helper。
- 远程服务器页面显示的 Helper 版本和最新构建一致。
- 新增远程 capability 已在 Helper 中实现，并在远程功能对齐表中标注状态。
- README、CHANGELOG、release note 和用户手册均已更新。
- 至少用一台真实远程主机完成健康检查、Helper 安装/更新、供应商读取、设置保存和一个核心远程动作验证。

## 常见问题

**为什么远程页面提示 Helper 缺少能力？**

桌面应用已经支持该功能，但远程主机安装的 Helper 还是旧构建。请在“远程服务器”页面更新 Helper。

**为什么远程工具在终端可用，应用内显示不可用？**

应用通过 SSH 非交互 shell 执行命令，加载的 PATH 可能和你手动登录终端不同。需要把工具路径写入非交互 shell 也能读取的启动文件，或使用应用提供的安装/修复动作。

**为什么远程 API Key 编辑时不直接明文显示？**

远程 API Key 属于远程主机密钥。页面会脱敏展示，编辑时留空表示保留原密钥，重新填写才会覆盖。

**为什么远程更新检测有时返回 GitHub 403？**

Helper 更新检测会查询 GitHub release。未认证请求可能触发 GitHub rate limit。等待额度恢复后重试，或在发布流程中确认 release asset 已存在。

## Remote support matrix

| Workflow/control | Classification | Boundary and compatibility behavior |
| --- | --- | --- |
| Provider list/add/edit/remove/switch | Parity | Selected profile and secret route through Helper; shared Rust provider service owns validation and writes |
| Codex third-party switch | Parity + remote-adapted | Requires `codex-config-only` before mutation; key stays in remote provider config and never falls back to local invoke |
| Managed-auth list/status/remove/default/logout | Parity | Requires Helper `auth`; queries and mutations remain target-qualified |
| Managed-auth targeted re-login | Remote-adapted | Uses `auth-targeted-relogin`; older Helper returns upgrade-required before unsupported mutation |
| Managed-auth cancel | Remote-adapted | Uses `auth-cancel-login`; older Helper cancellation degrades without terminating the session |
| Codex account identity/quota | Parity + remote-adapted | Account ID and quota queries use the selected target and capability state |
| Provider model discovery, including Pi | Remote-adapted | Remote targets always use the saved remote provider through Helper; unsaved keys never trigger local fetch |
| Manual session usage sync | Remote-adapted | Shown only with `usage-manual-session-sync`; explicitly initiated by the user |
| Background automatic session scan | Unsupported/local-only | Desktop background lifecycle only; not advertised by remote settings |
| SQL/WebDAV/S3/backup restore | Parity | Desktop and Helper call the shared Rust restore service; failure preserves previous state |
| Prompt restore protection | Parity | Managed prompts update through shared service; handwritten prompt content is retained when no managed prompt is enabled |
| OpenCode Go/Token Plan | Remote-adapted | Account/provider lookup runs on selected Helper target |
| Routing runtime | Remote-adapted | Remote runtime lives inside the long-lived Helper session; command errors do not tear down transport |
| Desktop proxy takeover, tray, terminal/Otty, deep links | Unsupported/local-only | Hidden or kept outside remote pages; no remote action invokes local side effects |
| Updater/restart/database recovery UI | Unsupported/local-only | Desktop commands avoid mandatory `AppState` in recovery mode |

## Validation recorded before release preparation

- Frontend: typecheck and 194 files / 1215 tests passed.
- Rust: 2874 library tests passed, 5 ignored; all integration targets passed, including 44 provider-service tests.
- Helper: CLI-focused tests and `cc-switch-remote-helper` check with `proxy-runtime` passed.
- Scripts: 13 tests passed.
- Schema/session: v17→v18, fail-closed backup, cursor/tail fingerprint and preserved-mtime rewrites covered.
- Downgrade boundary: old `v3.20.1` Helper rejected a v18 database without changing its SHA-256.
- Final post-suite fixes used focused evidence only: model-fetch routing test, remote capability test, Rust library check, format and diff checks.

## Required evidence before publishing

The following require release infrastructure or user-controlled environments and remain mandatory before publication:

- build and inspect every platform artifact and signature;
- confirm the release tag points to the intended candidate commit;
- confirm generated `latest.json` URLs, asset names and signatures use updater key id `9BAF0EEE4E844E4C`;
- exercise a real SSH host and update its Helper;
- upgrade an installed fork `v3.20.1` through the normal About flow;
- upgrade through database recovery with no initialized `AppState`;
- confirm restart opens schema v18 while remote profiles remain local metadata and remote secrets/state remain on their hosts.

No tag, GitHub Release, updater metadata or remote Helper release was created during preparation.
